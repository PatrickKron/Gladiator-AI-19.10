# @gladiator/exchange (Phasen 4b/4c)

Ein TradingVenue-Interface für ALLE Börsen (CEX via ccxt, DEX via Hyperliquid/dYdX-SDKs). Order-Lifecycle: Idempotenz (clientOrderId), Retry bei TP/SL-Fehler, Reconciliation beim Start (Börse = Wahrheit), Websocket-Fills.
Regeln: Orders NUR nach grünem Risk-Gate (`@gladiator/risk`); niemals Withdraw-Fähigkeit; Paper/Testnet-Default; Position nie ungeschützt offen lassen. Spec: 06_, Abnahmen B4b/B4c.
Live-Swaps (swap/live.ts): NIE eine Aggregator-Transaktion blind signieren. Angebote: Menge = ANGEFRAGTE Menge (nicht die vom Aggregator genannte), Mindestmenge selbst rechnen, keine Plattform-Gebühr; live zusätzlich Verlust unabhängig über DexScreener-Kurse (`independentLossPct` im Swap-Service). Solana: `assertJupiterSwapTx` (nur Jupiter-Swap-Bausteine für die eigene Wallet, kein Transfer/Approve/SetAuthority an Fremde, Prioritätsgebühr gedeckelt; GENAU EIN `route`/`shared_accounts_route` laut IDL dekodiert: Befugnis + Ziel-Konto = eigene Wallet, Menge/erwartete Menge/Slippage = Angebot, keine Plattform-Gebühr); EVM: `assertKyberSwap` (Calldata dekodiert: Empfänger = eigene Wallet, Tokens/Menge/Mindestmenge/value = Angebot, keine Fremdgebühren, keine Teilausführung). Tx-Hash vor dem Senden festhalten; Fehler NACH dem Senden = `pending` (Ausgang unklar), nie „nichts passiert“. Unmittelbar vor dem Signieren Freigabe/Order erneut prüfen (`beforeSign`).
