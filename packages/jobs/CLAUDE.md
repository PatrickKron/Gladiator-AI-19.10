# @gladiator/jobs (Phasen 3+)

BullMQ-Worker (Redis :6380): Markt-Scans, Position-Monitoring, Nacht-Pipeline (Backtests/Optimierung/Briefing), Kalender-Sync.
Regeln: Jobs idempotent + beobachtbar (strukturierte Logs, Metriken); keine losen setInterval-Loops (Alt-Fehler); Fehler → Alarm, nicht Stille. Spec: 04_ §2, 08_ §5/§7.
Nacht-Optimierung (`optimization.ts`, So 03:00 UTC): je Paper-Strategie (+ SMC Core auf Basis-Symbolen 4h) kleines Grid im Walk-Forward (IS 1000 / OOS 250 Bars, Warmup 250, ≥ 3 OOS-Fenster), Vergleich mit der aktuellen Version auf denselben OOS-Fenstern; nur bei klarem Vorsprung (`judgeOptimization` in @gladiator/backtest) eine Zeile in `optimizations` (status done, `results.review.state` = open) + Audit. Ändert NIE eine Version — übernehmen (→ draft) und promoten macht Patrick.
Screen-Alarme (`screen-alerts.ts`, alle 5 min): gespeicherte Screens mit `alert` auf echten DB-Kerzen rechnen (Auswertung aus @gladiator/indicators, eine Wahrheit mit der Seite) und NUR neue Treffer melden (`screens.last_matches`), Art `screen` über `notifySafe`. Nie Fakes, Fehler je Screen, Lauf geht weiter.
Asset-Register (`asset-register.ts`, Patrick 2026-10-25): EIN Dienst `registerAsset` für jedes „Asset hinzufügen/wählen“ (product.addAsset, market.ensureCandles/ensureStockCandles) — Symbol gegen die echte Quelle prüfen (Binance-Paarliste, Yahoo-Suche/-Chart, notfalls vorhandene Kerzen), Kerzen laden, Zeile in `assets` (`candle_venue` + `data_symbol`; Katalog-Asset wiederverwenden, sonst Paket `user-markets` „Eigene Märkte“), optional Stern, Audit `asset.register`. Unbekanntes Symbol oder keine Kerze → Fehler, nie eine leere Zeile. `registeredAssets()` = Basis + Favoriten aller User + Hinzugefügte, mit Quelle, nach Priorität (Basis, jüngster Stern, jüngste Zeile). `scanUniverse()` bleibt Krypto (Basis + Favoriten nach jüngstem Stern, Cap `MAX_UNIVERSE` 40) für Krypto-Verbraucher.
Kerzen-Refresh (`candle-refresh.ts`, alle 15 min): je registriertem Asset (Cap 150) Binance über `ensureCandles` (max(ts) nur venue binance), Yahoo über `loadYahooCandles` (1d · 1h · 15m, kleinstes Fenster ab letzter Kerze), Twelve Data nur mit Key (1h/1d) — sequentiell mit Pause, Fehler je Symbol, Lauf geht weiter. Kein 4h für Yahoo gespeichert — Scans bauen es aus 1h (`aggregateCandles`).
Preis-Alarme (`alerts.ts`): Quelle je Alarm (`price_alerts.venue`; Altbestand: Krypto-Paar → Binance, sonst Register) — Binance = Markpreis, Yahoo/Twelve Data = Schluss der neuesten FRISCHEN Kerze (`latestFreshClose`); veraltet → übersprungen + geloggt, nie ausgelöst.
Signal-Scan je Quelle (A1, 2026-10-27, `scan-targets.ts`): Universum = `registeredAssets()` (Binance, Yahoo, Twelve Data; Cap `MAX_SCAN_TARGETS` 80, Krypto ≤ 40), Klasse aus dem Register (Futures nur bekannte Rohstoffe, Fonds/Index-Futures übersprungen + geloggt), `signals.venue` (0044) in Insert + Dedupe. Nur abgeschlossene Kerzen (`closedCandles`), Börsen-Quellen 4h aus 1h (UTC-Buckets, nur abgeschlossene), veraltete Reihen → kein Signal. DSL-Scan: Symbol über das Register, Krypto-Paar sonst Binance. Review und Ausführung bis A2 nur `venue = 'binance'` (`signalExecutionBlock`, ehrlicher Grund). Forex ohne Volumen erzeugt mit SMC Core keine Signale (Volumen-Bestätigung Pflicht).
